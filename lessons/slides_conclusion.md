# What did we actually learn?

Not whether AI is good or bad.

Whether we can see what it did.

Note:
Bring the room back from the exercises. The workshop has not been about taking a side on AI. It has been about making model output inspectable enough that a researcher can decide what to do with it.

---

## The model gave us output

It gave us codes.  
It gave us quotations.  
It gave us explanations.  
It gave us ambiguity notes.

That is not the same thing as giving us findings.

Note:
This is the key distinction. The output may be useful, but it is not self-validating. A polished result is still only a claim until someone checks it against the source.

---

## Three different problems

A quotation can be inaccurate.

A quotation can be real, but attached to the wrong code.

A passage can support more than one defensible reading.

Those are not the same problem.

Note:
Refer back to Lesson 3. The point is to avoid the lazy conclusion that “the AI was wrong.” Wrong how? Misquoted? Overinterpreted? Underdefined code? Ambiguous passage? Each problem has a different remedy.

---

## The codebook is part of the system

If the code is vague, the model will use the vagueness.

So will humans.

A better prompt cannot fully fix an unstable codebook.

Note:
This is where the workshop becomes a methods lesson rather than a tool demo. A model can expose ambiguity, but the researcher still has to decide what the category means.

---

## What AI was useful for today

It made disagreements visible.

It applied the same codebook quickly.

It produced evidence we could inspect.

It forced us to ask where our definitions were too loose.

Note:
Keep this balanced. Do not turn the ending into a warning-only slide. The tool was useful because it created an object for methodological discussion.

---

## What AI did not replace

It did not decide what matters.

It did not know the ethical stakes of the material.

It did not make the source unnecessary.

It did not repair the codebook for us.

Note:
This is the human judgment slide. The point is not that humans are always consistent or models are always suspect. The point is that the responsibility for interpretation and documentation remains with the researcher.

---

## A workflow you can take home

Small corpus.  
Human coding.  
Draft codebook.  
AI first pass.  
Evidence audit.  
Codebook revision.  
Test again.

Note:
Say this as a practical workflow. The first AI run is not the end of the process. It is a stress test.

---

## Before using this on your own data

Ask:

Can this material be pasted into the tool?

Would I be comfortable documenting this workflow in a methods section?

Can I check the evidence without trusting the model?

What would I do if the model disagrees with me?

Note:
This is the governance close, but keep it practical. Do not make it sound like institutional policy advice. The point is to slow down before turning a classroom exercise into a research workflow.

---

## Closing question

What would you trust this tool to code?

And what would you never hand it?

Note:
Use this as the final discussion prompt if there is time. Encourage concrete answers: a kind of document, a stage of the workflow, a type of code, or a type of evidence.
